# Simulation directories and figure outputs

Regrouping and TEA use the following directory responsibilities:

```text
<module>/
  run.py
  results/
    reference/          Frozen numerical results and reference plotting caches
    figure_data/        Current plotting tables, indices and dimension tables
    runs/<mode>/        Numerical results generated by a new run
    model/              Regrouping: checkpoint and training state
    baseline/           TEA: numerical baseline before additional targeted RPT
  visualization/
    *.py                Plotting code
    outputs/
      panel_*.png       Individual panels directly in this directory
      Figure_*_overview.png
      panel_manifest.json
      runs/<mode>/      Figures generated by a new run
```

For regrouping, the module-root `model/` contains model code and `inputs/` contains simulation inputs and their runtime manifest. TEA uses root-level `tea_model.py`, `results/baseline/` and `reference_integrity.json` for packaged reference verification. Captions and figure guides accompany `visualization/`. Generated CSV/Excel tables, compressed draws, weights and numerical records belong in `results/`.

| Framework | Delivered panels | Command from release root |
| --- | --- | --- |
| Regrouping, Figure 7 | Sorting and regrouping simulation/visualization/outputs/ | python run.py regrouping --mode figures |
| TEA, Figure 8 | Techno-economic-environmental assessment/visualization/outputs/ | python run.py tea figures |

Figure 7 includes twelve 600-dpi panels. Figure 8 includes twelve 300-dpi panels and six assembly assets. Overviews and panels share the output directory. Numerical plotting data are stored in results/figure_data/, with locations recorded by panel_manifest.json.

## New runs and custom outputs

Default demo/full/model numerical outputs go to the module's `results/runs/<mode>/`; corresponding figures go to `visualization/outputs/runs/<mode>/`. A full run retains plotting data and density caches alongside its numerical results. Regrouping's training script defaults to `results/runs/training/`; its complete training-grid entry uses `results/runs/training_grid/`.

For simulation entry points, `--output <new-root>` creates the same `results/` and `visualization/` structure beneath that root. For example, `python run.py tea demo --output runs/tea_check` writes numerical results to `runs/tea_check/results/runs/demo/` and figures to `runs/tea_check/visualization/outputs/runs/demo/`. New simulation runs preserve delivered reference values. LFP/NMC model training and inference use their own `main.py`; their `OUTPUT_DIR` is controlled by the adjacent `config.py`.

Regrouping `--mode verify` checks delivered reference results by default. With `--output <new-root>`, it checks full-run results and figures under that root. TEA `verify` checks full-run numerical results under the selected root.

## Supplied reference data

Frozen numerical results are in each module's results/reference/. Regrouping reference plotting tables are in results/reference/figure_source/, weights in results/model/, and the associated MAT in inputs/.

Figure 8 uses the supplied summaries and compact density caches for the 800,000-draw reference analysis. Figure-only execution validates these tables and caches before rendering. The `full` command runs the Monte Carlo analysis and produces numerical outputs for subsequent verification and plotting.

Source-data indices generally use relative paths; custom exports across drives use absolute paths where necessary. Keep the complete module structure when moving outputs so the indices continue to resolve.
